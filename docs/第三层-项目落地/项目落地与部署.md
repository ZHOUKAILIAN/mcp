# 项目落地与部署

## 1. 项目结构

本项目是 pnpm 多软件包仓库：

```text
mcp/
  packages/weather-mcp/
  packages/xiaocan-workflow-mcp/
```

工作区配置：

```text
pnpm-workspace.yaml
```

## 2. 本地安装和验证

```bash
pnpm install
pnpm typecheck
```

## 3. 服务启动

### 天气 MCP

```bash
pnpm start:weather
# 默认端口 7777
# 本地开发 SSE 地址：http://localhost:7777/mcp
```

### 小蚕流程 MCP

```bash
pnpm start:xiaocan
# 默认端口 7788
# 本地开发 SSE 地址：http://localhost:7788/mcp
```

两个软件包当前的 `start` 命令包含 `tsx --watch`，定位是开发启动命令。当前 MCP 客户端仍以 `stdio` 方式使用服务；仓库中的 HTTP SSE 入口主要是后续服务器化的基础。生产环境不能依赖 watch 模式。

## 4. 配置

### 天气

```text
APPCODE=<服务器密钥>
PORT=7777
```

### 小蚕

```text
PORT=7788
XIAOCAN_TOKEN=<服务器密钥>
XIAOCAN_USER_ID=<私有值>
XIAOCAN_SILK_ID=<私有值>
XIAOCAN_CITY_CODE=310100
XIAOCAN_LAT=31.2286
XIAOCAN_LNG=121.4584
```

真实值只能通过服务器密钥或环境变量注入。`.env.example` 只允许放占位值。

## 5. 从 stdio 切换到服务器 SSE

当前状态：

- 实际客户端接入方式：`stdio`。
- 仓库代码已有 HTTP SSE 入口：`/mcp` 和 `/mcp-messages`。
- 服务器部署和远程客户端配置：尚未完成。

目标状态：

- 两个 MCP 分别部署到服务器。
- MCP 客户端通过 HTTPS SSE 地址连接。
- 用户不再需要在本地启动 MCP 子进程。

切换步骤：

1. 先以单用户方式部署天气 MCP，验证远程 SSE 通信。
2. 再部署小蚕 MCP，验证凭据只属于受信任的单用户服务。
3. 在反向代理中配置 HTTPS、身份验证和访问日志。
4. 修复 SSE 会话管理，避免多个客户端共用一个传输层引用。
5. 将客户端配置从 `stdio` 命令改为服务器 SSE 地址。
6. 完成断线重连、错误处理和安全检查后，再停止本地 `stdio` 方式。

## 6. 服务器部署目标

当前推荐的第一阶段部署模型是：

- 两个 MCP 分别部署。
- 每个服务单独进程和端口。
- 单用户、私有访问。
- 前置 Nginx、Caddy 或 API Gateway。
- 外部使用 HTTPS 和鉴权，内部再转发到 Node.js 进程。
- 使用 systemd、Docker 或其他固定进程托管，不使用 `tsx --watch` 作为生产方案。

推荐拓扑：

```text
MCP 客户端
   |
 HTTPS + 身份验证
   |
 反向代理 / 网关
   |                 |
 :7777 天气       :7788 小蚕
```

## 7. 当前部署阻塞项

在以下问题解决前，不应直接公网暴露：

1. HTTP 层没有内置鉴权。
2. SSE 传输层 只有单个共享连接引用。
3. 小蚕凭据是进程级全局状态。
4. 流程 JSON 不支持多实例并发写入。
5. 没有健康检查、限流、请求体限制和结构化审计。
6. 小蚕 API 的官方授权状态未记录。
7. 天气接口存在上游证书域名不匹配，目前保留兼容性例外。

## 8. 后续部署改造顺序

1. 保留并收窄天气接口的 TLS 兼容逻辑，同时清理测试脚本中的真实 AppCode。
2. 明确单用户私有部署模型，先不支持多租户。
3. 增加 HTTPS 反向代理和客户端身份验证。
4. 为 MCP 会话独立管理传输层，或迁移到 Streamable HTTP。
5. 将数据路径配置化并挂载持久化目录。
6. 需要多用户时迁移到数据库，并设计租户和凭据隔离。
7. 增加健康检查、日志、限流、备份和回滚方案。
