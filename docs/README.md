## 阅读顺序

1. 先读第一层，理解产品边界和两个 MCP 的职责。
2. 再读第二层，确认代码当前真实行为；代码与第一层冲突时，记录漂移，不静默改写。
3. 涉及启动、部署、依赖和配置时读第三层。
4. 涉及提交、验证、审查和发布时读第四层。
5. 仅在处理本机环境、临时数据和开发会话时读第五层。

后续新增文档时，应先判断它属于哪一层，不能只按文件类型或目录名称归类。
