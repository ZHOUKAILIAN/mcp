# MCP 产品定义

## 文档状态

- 状态：当前产品定义
- 更新原则：产品边界以本文为准；当前代码行为以第二层实现基线为准
- 适用范围：`weather-mcp` 和 `xiaocan-workflow-mcp`

## 1. 产品概述

本项目提供两个可被 MCP 客户端连接的独立 MCP 服务：

1. **天气 MCP**：部署为服务器服务，供 MCP 客户端通过 SSE 地址查询城市天气和 24 小时天气预报。
2. **小蚕流程 MCP**：部署为服务器服务，供 MCP 客户端通过 SSE 地址连接小蚕相关接口，并管理霸王餐返现流程记录。

两个 MCP 是独立软件包、独立进程和独立服务入口，不要求合并成一个服务。当前客户端主要通过 `stdio` 使用它们，后续目标是将两个服务部署到服务器，并改为通过 SSE 地址连接。用户不再需要在本地启动 MCP 子进程。

## 2. 天气 MCP

### 目标

让 MCP 客户端能够通过城市名称获取天气信息，支持客户端读取天气预报。后续通过服务器 SSE 地址连接，不要求用户在本地启动天气 MCP。

### 产品能力

- 根据城市名称查找城市 ID。
- 获取该城市的 24 小时天气数据。
- 当前公开工具：`get-weather`。

### 非目标

- 不代替天气 App 的完整功能。
- 不执行通知、自动带伞提醒或其他外部动作，除非未来另有产品定义。

## 3. 小蚕流程 MCP

### 目标

为用户提供一个由 MCP 客户端通过 SSE 地址调用的小蚕霸王餐辅助服务，包含：

- 小蚕活动和店铺查询。
- 小蚕活动详情查询。
- 用户主动触发的抢单操作。
- 已抢订单查询。
- 地址和城市信息查询。
- 返现/评价材料提交。
- 订单返现流程记录、状态推进和下一步建议。

### 产品边界

当前产品包含第三方接口操作能力，不再定义为“纯本地流程助手”。其中：

- 查询类工具读取小蚕服务数据。
- 抢单和提交材料属于有副作用的写操作，必须由用户明确触发。
- 流程工具负责本地流程记录，不自动替用户完成外卖平台下单。
- 评价草稿只能基于用户提供的真实体验内容生成，不自动发布评价，不应编造体验。

### 小蚕接口状态

当前代码访问：

```text
https://gw.xiaocantech.com/rpc
```

当前代码使用小蚕账户凭据、设备标识和请求签名字段。产品定义只记录这一事实，不将其解释为官方授权证明。

在官方授权、服务条款和凭据安全状态未明确前，本产品按**私有、单用户、受限服务**理解，不定义为可直接公开提供的多用户服务。

### 非目标

- 不自动操作美团或饿了么 App 下单。
- 不自动发布评价。
- 不生成虚假评价内容。
- 不自动化手机 UI。
- 不绕过登录、风控、WAF、IP 限制、设备检查或速率限制。

## 4. 关键用户流程

### 天气

```text
MCP 客户端 -> get-weather(cityName) -> 城市查询 -> 24 小时天气结果
```

### 小蚕接口流程

```text
登录配置
  -> 搜索店铺/活动
  -> 查询活动详情
  -> 用户确认后抢单
  -> 查询已抢订单
  -> 用户完成外卖订单和真实评价
  -> 用户确认后提交返现/评价材料
```

### 小蚕流程

```text
candidate
  -> claimed
  -> takeaway_ordered
  -> received
  -> reviewed
  -> ready_to_submit
  -> submitted
  -> cashback_received
```

非终态可转为 `cancelled`；终态不再继续推进。

## 5. 产品级安全要求

- 真实 token、AppCode、用户 ID、设备 ID 不进入代码、文档、示例或 Git。
- 抢单、提交材料等写操作必须保留用户主动触发语义。
- 远程部署必须有 HTTPS、客户端鉴权、单用户/租户隔离和操作审计。
- 没有明确授权时，不将小蚕接口能力暴露给不受信任的第三方用户。
