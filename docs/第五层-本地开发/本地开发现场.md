# 本地开发现场

## 1. 定位

第五层只保存当前机器、当前用户或当前会话所需的开发连续性，不是产品定义、实现真理源或共享治理规范。

## 2. 本地敏感和运行时文件

以下内容必须留在本地或服务器受保护运行目录，不提交到 Git：

```text
.env
data/
auth.json
~/.xiaocan-mcp/auth.json
```

其中：

- `.env`：本地环境变量和 密钥。
- `data/workflows.json`：本地流程运行数据。
- `~/.xiaocan-mcp/auth.json`：小蚕登录凭据。
- 临时日志、抓取结果、调试输出：只用于当前现场排查。

## 3. 本地运行

```bash
cp .env.example .env
pnpm install
pnpm start:weather
# 或另开终端
pnpm start:xiaocan
```

本地端点：

```text
http://localhost:7777/mcp
http://localhost:7788/mcp
```

## 4. 本地调试规则

- 使用占位凭据或本地 密钥，不把真实值写进源码。
- 调试输出不得打印完整 token、认证请求头或完整敏感响应。
- 临时测试脚本和实验性调用保持在本地，不自动提升到正式软件包入口。
- 本地 JSON 数据可以删除或重置，但删除前应确认不需要备份。
- 如果临时实验改变了产品能力，必须先回到第一层和第二层进行正式变更，而不是只留在本地。

## 5. 当前已知本地例外

`packages/weather-mcp/src/api/test-cityid.ts` 是历史临时测试脚本。它不属于生产启动链路；使用前必须确认其中没有真实 AppCode，并优先改为读取环境变量。

## 6. 写回边界

| 内容 | 写回位置 |
|---|---|
| 稳定产品边界 | 第一层 |
| 当前代码行为 | 第二层和源码 |
| 启动/部署配置 | 第三层 |
| 协作和验证规则 | 第四层 |
| 临时日志、token、运行数据 | 留在第五层，不写入正式文档 |
